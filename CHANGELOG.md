Profile reached from a schedule header button; onboarding got a sign-out so a gym-less user isn't stranded.
- **M3 Schedule + detail (S4/S5)** — schedule home reads `class.mine` over a rolling 7-day window, grouped by day (Today first), rows = time · title · "N spots left", empty state, tap → detail. The `matops://join/<code>` deep link (expo-router file route) **and** an in-app paste path (pure `extractInviteToken`); a signed-out invite carries the token through sign-in via `?redirect`. Slim S3 pending banner on the schedule.
- **M1 Sign in (S1)** — `app/sign-in.tsx` passwordless magic link (email only). `callbackURL` is rewritten by `@better-auth/expo` into the `matops://` deep link so the link bounces back into the app. Server `trustedOrigins` `expo://` → `matops://` (required — the expo plugin only appends the session cookie to the verify-redirect when it starts with a trusted origin).
- **M0 Shell + retire demo** — renamed the app scheme `expo → matops` (+ bundle ids `com.matops.app`); rewrote `app/index.tsx` as an auth gate (no session → sign in · no active academy → join · else → schedule); a tiny NativeWind UI kit (`Screen`/`Button`/`TextField`/`Banner`/…). - **2.2 Materialization (lazy + bounded cron)** — new tenant-scoped `class` table (migration `0007` + RLS `0008`; `starts_at` UTC, `booking_count`, `status scheduled|cancelled`, `UNIQUE(template_id, starts_at)`). Pure DST-aware `computeOccurrences` in `@matops/domain` (local minutes + IANA zone → UTC instants, tested across spring-forward **and** fall-back). `materializeTemplate`/`runMaterializationSweep` in `@matops/db` (idempotent `onConflictDoNothing`, `generated_until` cursor, stale-first + row limit + soft time budget). Tests 37 → 40.

## Phase 1 — Identity & tenancy (web-first)

- **Phase 1 verified live on Neon** — walked the exit test end to end on the real DB: magic-link sign-in → create academy → active owner (RLS scoped) → invite link → second user joins pending (no academy role) → owner approves → role granted + active. Never-ownerless guard and owner-only role gates confirmed. Removed the T3 demo web screens (`posts`/`auth-showcase`); the `post` router stays only for the deferred Expo demo. Added ADRs [28](docs/issues/28-invite-link-model.md) (custom invite table) + [29](docs/issues/29-pending-role-model.md) (pending holds no role). Tests 10 → 28.
- **1.6 Multi-academy switcher (web)** — `academy.listMine` (web lens = owner/instructor/pending-instructor via `isWebLensMembership`) + `academy.setActive`; a nav dropdown shown only with 2+ academies switches `activeOrganizationId`, so RLS scope follows.
- **1.5 Roster** — `membership.roster` + owner actions `remove`/`suspend`/`promote`; pure `canRemoveOrDemote` enforces **never ownerless** (can't drop the last active owner); removal soft-revokes (keeps the row). Web roster with per-member actions.
- **1.4 Uniform approval gate** — `membership.approve`/`reject`; pure `approveMembership` grants `role := invitedRole` + `status := active`; `canApprove` guards non-pending rows. Web "Pending approvals" section.
- **1.3 Student self-join → pending** — `membership.join` (protected): resolves the token, saves the minimal profile (name + phone; email comes from magic-link), creates a **pending** membership holding the harmless default role with the intended role on `invitedRole`. Idempotent; first academy becomes active. `JoinAcademySchema` validator. (Web `/join/[token]` route serves instructor self-join; the Expo student screen is deferred.)
- **1.2 Invite links** — new **non-RLS `academy_invite`** table (migration `0004`) + `invite` router (`list`/`create`/`rotate`/`revoke` owner + public `resolve`); one live link per role (partial unique index), rotate = revoke + mint. Pure `isInvitableRole` (never `owner`). Web invites panel with copy/rotate.
- **1.1 Owner onboarding** — `academy` router (`create`/`current`/`listMine`/`setActive`); creating an academy makes you an **active owner at once** via an `afterCreateOrganization` hook + `member.invitedRole` field (auth-schema regenerated). Web "Start a gym" replaces the T3 demo home; pure `slugify` for the org slug.

## Phase 0 — Foundations

- **Neon wired + RLS verified live** — connected a Neon database, applied all migrations, and confirmed the tenant isolation on real Postgres (A sees only its rows; cross-tenant write blocked). Added migration `0003_grant_app_role.sql` (`GRANT matops_app TO current_user`) — required because a managed-Postgres connection role is not a superuser and can only `SET ROLE` to a role it belongs to. PGlite (superuser) had masked this; noted in ADR 12.
- **0.6 CI/CD** — added a `test` task (turbo + root script) and a CI `test` job (runs on PGlite, no external DB) plus a `drizzle-kit check` migration-consistency step. CI now gates lint · format · typecheck · test · migration-check. Removed the template's `FUNDING.yml`. **Not provisioned (needs accounts):** Vercel preview deploys and EAS builds are wired via their dashboards, not in-repo. **Env:** `.env.example` is permission-locked in this environment and still shows the Supabase placeholder — set `POSTGRES_URL` to a Neon pooled string and `AUTH_SECRET` in your `.env` (the Neon requirement is documented in `CLAUDE.md`, `packages/db/src/client.ts`, and `drizzle.config.ts`).
- **0.4 tRPC procedure tiers** — added the tenant middleware `enforceTenant`: it reads `session.activeOrganizationId` as the academy id, loads the caller's membership, and runs the whole resolver inside `withTenant(academyId, …)` so `ctx.db` is RLS-scoped. Tiers: `publicProcedure` · `enrolledProcedure` (any member, incl. pending) · `memberProcedure` (active) · `staffProcedure` (owner/instructor) · `ownerProcedure`. The role/status checks are pure predicates in `@matops/domain` (`isActiveMember`/`isStaff`/`isOwner`, unit-tested). New `system` router: public `health` + tenant-scoped `ping` (the Phase 0 exit proof).
- **0.5 Better Auth (org + magic-link)** — added the Organization plugin (org = academy, `member` with a `status` field, `invitation`, `session.activeOrganizationId`), the magic-link plugin, and a `phone` field on the user. Custom roles `owner`/`instructor`/`student` via access control in a client-safe `@matops/auth/permissions` module. Dropped Discord OAuth. Regenerated the Drizzle auth schema (migration `0002_auth_org.sql`) and rewired the Next.js + Expo auth clients and sign-in UIs to magic link. Made `@matops/api` source-consumed (types from `src`, no `.d.ts` emit) because the tRPC `AppRouter` embeds the full Better Auth `Auth` type, which is too large to serialize into a declaration file.
- **0.3 Tenant seam (RLS)** — swapped the DB to the `pg` driver so requests can run an interactive transaction; added `withTenant(academyId, fn)` (`packages/db/src/tenant.ts`) that does `SET LOCAL ROLE matops_app` + `set_config('app.academy_id', …, true)`. Migration `0001_tenant_rls.sql` creates the restricted role, grants, and a `tenant_probe` table with an RLS policy. A PGlite-based leak test (`test/rls.test.ts`, 5 cases) proves isolation with no external DB. `academy_id` is text (no `::uuid`); queries fail closed when the GUC is unset.
- **0.2 DB package** — retargeted from `@vercel/postgres` (HTTP) to `pg` on the Neon `-pooler` endpoint; versioned migrations (`drizzle-kit generate` → `migrations/`), a `_health` table, and a `seed` script. Migrations run against Neon's direct endpoint (drizzle strips `-pooler`). Health smoke test in `test/health.test.ts`.
- **0.1 Monorepo scaffold** — scaffolded from `create-t3-turbo`: Turborepo + pnpm, `apps/{nextjs,expo}` + `packages/{api,auth,db,validators,domain,ui}` + `tooling/*`. Renamed scope to `@matops/*`, dropped the unused `tanstack-start` app, added the framework-free `packages/domain`, and promoted the planning docs into `docs/`.
