## Rank only goes up — monotonic promotion (ADR 41 addendum)

- **A member's rank can now only be bumped, never lowered** (ADR [41](docs/issues/41-member-rank-and-notes.md) addendum) — belts and stripes reflect real BJJ/Judo grading, where a rank is never taken away, so a downward `set` is treated as a mistake, not a demotion. Two pure helpers in `packages/domain/src/rank.ts` do it: **`compareRank(discipline, a, b)`** orders two ranks in one ladder (belt position dominates; stripes only break a same-belt tie — *White · 4 stripes* is still below *Blue · 0*), and **`isRankRegression(discipline, current, next)`** is true only when `next` sits strictly below the current rank. The `rank.set` mutation now throws `BAD_REQUEST` on a regression. **Correction path = clear-then-set:** `rank.clear` removes the rank (append-only promotion history is kept) so the next set is unconstrained — the web O4 panel finally **wires up a per-discipline Clear control** (the router had it; the UI never showed it), seeds the Set form to the member's current rank, and disables belt/stripe options below it. No schema / migration / RLS change. Green: new `compareRank` + `isRankRegression` unit tests in `rank.test.ts`; lint · typecheck · tests.
