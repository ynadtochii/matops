One line per shipped slice (see `docs/delivery.md` §4). Newest first.

## Phase 4 — notifications & polish (slices 4.1–4.3)

- **4.3 States + design pass** — a shared **state system** on both clients so every data view behaves the same: `SkeletonRows` (loading), `EmptyState` (an invitation — title + what to do next), `ErrorState` (names the failure + a retry). Web `apps/nextjs/src/app/_components/states.tsx`; mobile mirror in `apps/expo/src/components/ui.tsx` (same tokens, ADR 11). Applied across web home/schedule/roster/attendance/templates and mobile schedule/class/check-in. Fixed **two latent bugs** where a failed fetch masqueraded as "no data" — web `home` fell through to onboarding, mobile `schedule` showed "no classes" — both now show an error + retry. Thin **S7 Push notifications** toggle on the mobile profile: one switch that registers/unregisters this device's push token (off = nothing sent), no server preference. Soft-capacity red + ≤3-tap booking already shipped in S5. Confirmed live in the browser. Green: `lint` (15/15), `typecheck` (17/17), `test` (133).


- **4.1 notifications package** — new `packages/notifications`, a **pure serverless transport** (ADR [34](docs/issues/34-notifications-layering.md)): `sendPush` (Expo Push, batched/chunked to 100) + `sendEmail` (Resend). **Never throws**, no `@matops/db` dependency, no-ops when unconfigured. Message text is pure builders in `@matops/domain/notify.ts` (`buildCancelledMessage`/`buildClassChangeMessage`/`buildApprovalMessage`/`buildReminderMessage` + `formatWhen` + `isInReminderWindow`). Push tokens live **outside the tenant seam** — `push_token` (migration `0014`, keyed by `user.id`, no `academy_id`/RLS, verified live on Neon); `pushToken.register`/`unregister` on `protectedProcedure` (base-connection write, no `ctx.db`). Mobile registers on sign-in / unregisters on sign-out via `expo-notifications` (`apps/expo/src/utils/push.ts` + `components/push-sync.tsx`).
- **4.2 Events** — the three `TODO(phase 4)` hooks are wired through `packages/api/notify.ts` (resolves academy name + recipient tokens/emails on the base connection, builds the message, sends): **class cancelled** → push + email booked students; **class time/instructor change** (`classChange.shouldNotify`) → push + email; **membership approved** → welcome push. Each is awaited (before the serverless response freezes) but swallows its own errors, so a send never fails the mutation. Class-**reminder** sweep = `claimDueReminderClasses` (base connection, atomic `reminder_sent_at` NULL→now claim in `0014`) + `runReminderSweep` + the protected `/api/cron/remind` route; the **frequent cron schedule** is deferred to Phase 5 (needs a sub-daily cron — ADR 34), so no `vercel.json` entry yet. Mobile tap-to-navigate handler. Green: `lint` (15/15), `typecheck` (17/17), `test` (**133** — +13 domain notify, +3 notifications transport); migration `0014` applied + probed live on Neon.

## Phase 3 complete — attendance, QR check-in, public drop-in (slices 3.2–3.5)

- **3.5 Public drop-in form** — new `drop_in` table (migration `0013` + owner-read RLS) and a `dropIn` router whose `submit`/`academyInfo` are the **first public (unauthenticated) procedures** — an enumerated tenant-seam exception that writes on the trusted base connection (docs/issues/12, 25). Public web page `/checkin/[academyId]` captures a first-time visitor (name, surname, phone, email optional, **required consent** via `z.literal(true)`) as a lead + attendance, **deduped by phone** (`ON CONFLICT` bumps `visit_count`), resolving today's class server-side (else a general lead). Owner O4 gets a Drop-in leads section; O6 shows the printable venue check-in link. Pure rules `canSubmitDropIn`/`normalizePhone`.
- **3.4 QR self check-in** — new `checkin` router (`today`/`checkIn` on `enrolledProcedure`). Check-in is **book + attend** in one atomic step (soft cap — present even if full; a pending member checks in provisional). `resolveCheckInClass` (pure) resolves the current/next class **server-side** (the Expo app has no `@matops/domain` dep); mobile S8 `checkin` screen confirms + marks present. No camera in v1 — uses the active academy; the physical QR routes no-app visitors to the drop-in form.
- **3.3 Attendance** — migration `0012` adds the attendance axis to `class_participation` (`attendance_status`, `attended_at`, `marked_by`) + a `none` booking value (walk-ins). New `attendance` router (`staffProcedure`: `roster`/`mark`/`addWalkIn`/`members`) + the O5 web screen: pick a class in the 14-day backfill window, mark present/absent, add a walk-in (booking `none` + present, never counted). Roster `visitCount` ("attended N×") is now real. Pure rules `canMarkAttendance`/`attendanceCounts`.
- **3.2 Provisional booking (owner view)** — `class.week` now returns a `pendingCount` (a provisional-only subquery); the owner-web schedule shows "N/cap · +M pending". The student-side "pending approval" tag shipped with 3.1.
- Green: `lint` (13/13), `typecheck` (15/15), `test` (**117** — 79 domain + 38 db). Migrations `0011`–`0013` applied + verified on Neon.

## Slice 3.1 — Book / cancel

- **3.1 Book / cancel** — new `class_participation` table (migration `0011` + RLS, same academy policy as `class`) and a `booking` router (`book`/`cancel` on `enrolledProcedure`, so a pending member books too). Booking is **never blocked** (soft cap, §4): the resolver runs an idempotent participation upsert (`UNIQUE(class_id, student_id)`; re-book flips `cancelled → booked`) then an atomic `booking_count` increment with **no capacity guard** — both inside the RLS request tx (docs/issues/13). **Two tiers** (docs/issues/22): an approved member books **confirmed** (counts); a **pending** member books **provisional** (recorded, tagged "pending approval", never counted). `class.get`/`class.mine` return the caller's `myBooking`/`myBookingTier`; mobile S5 gets a Book / Cancel button (full → "book anyway?" confirm) and S4 a "Booked" pill. Pure rules `bookingTier`/`canBook`/`capacityDisplay` in `@matops/domain`. Green: `lint` (13/13), `typecheck` (15/15), `test` (84 — +12 domain, +10 db booking/RLS).

## Hardening — Tenant-seam enforcement (fail-closed)

- **Tenant seam made fail-closed** (ADR [33](docs/issues/33-tenant-seam-enforcement.md), from an architecture audit). The tRPC base context no longer carries a db handle — the only db a resolver sees is the RLS-scoped `ctx.db` inside tenant procedures, so a non-tenant resolver that reaches for it fails at **typecheck**. Added the missing **lint guardrail** blocking the raw owner `@matops/db/client` in `packages/api/src/router/**` (confirmed firing). Fixed the **enrolled-tier fail-open**: new pure `canEnroll` excludes `suspended`/`removed` (was: any membership row). Made **"never ownerless" atomic** — `setMemberStatusIfNotLastOwner` does the check + write in one `FOR UPDATE` transaction, closing a concurrent-removal race. Follow-up tracked in ADR 33: split the runtime DB role from the table owner (Phase 5, needs Neon provisioning). Green: `lint` (13/13), `typecheck` (15/15), `test` (62).

## Phase 0 — Foundations

- **Neon wired + RLS verified live** — connected a Neon database, applied all migrations, and confirmed the tenant isolation on real Postgres (A sees only its rows; cross-tenant write blocked). Added migration `0003_grant_app_role.sql` (`GRANT matops_app TO current_user`) — required because a managed-Postgres connection role is not a superuser and can only `SET ROLE` to a role it belongs to. PGlite (superuser) had masked this; noted in ADR 12.
- **0.6 CI/CD** — added a `test` task (turbo + root script) and a CI `test` job (runs on PGlite, no external DB) plus a `drizzle-kit check` migration-consistency step. CI now gates lint · format · typecheck · test · migration-check. Removed the template's `FUNDING.yml`. **Not provisioned (needs accounts):** Vercel preview deploys and EAS builds are wired via their dashboards, not in-repo. **Env:** `.env.example` is permission-locked in this environment and still shows the Supabase placeholder — set `POSTGRES_URL` to a Neon pooled string and `AUTH_SECRET` in your `.env` (the Neon requirement is documented in `CLAUDE.md`, `packages/db/src/client.ts`, and `drizzle.config.ts`).
- **0.4 tRPC procedure tiers** — added the tenant middleware `enforceTenant`: it reads `session.activeOrganizationId` as the academy id, loads the caller's membership, and runs the whole resolver inside `withTenant(academyId, …)` so `ctx.db` is RLS-scoped. Tiers: `publicProcedure` · `enrolledProcedure` (any member, incl. pending) · `memberProcedure` (active) · `staffProcedure` (owner/instructor) · `ownerProcedure`. The role/status checks are pure predicates in `@matops/domain` (`isActiveMember`/`isStaff`/`isOwner`, unit-tested). New `system` router: public `health` + tenant-scoped `ping` (the Phase 0 exit proof).
- **0.5 Better Auth (org + magic-link)** — added the Organization plugin (org = academy, `member` with a `status` field, `invitation`, `session.activeOrganizationId`), the magic-link plugin, and a `phone` field on the user. Custom roles `owner`/`instructor`/`student` via access control in a client-safe `@matops/auth/permissions` module. Dropped Discord OAuth. Regenerated the Drizzle auth schema (migration `0002_auth_org.sql`) and rewired the Next.js + Expo auth clients and sign-in UIs to magic link. Made `@matops/api` source-consumed (types from `src`, no `.d.ts` emit) because the tRPC `AppRouter` embeds the full Better Auth `Auth` type, which is too large to serialize into a declaration file.
- **0.3 Tenant seam (RLS)** — swapped the DB to the `pg` driver so requests can run an interactive transaction; added `withTenant(academyId, fn)` (`packages/db/src/tenant.ts`) that does `SET LOCAL ROLE matops_app` + `set_config('app.academy_id', …, true)`. Migration `0001_tenant_rls.sql` creates the restricted role, grants, and a `tenant_probe` table with an RLS policy. A PGlite-based leak test (`test/rls.test.ts`, 5 cases) proves isolation with no external DB. `academy_id` is text (no `::uuid`); queries fail closed when the GUC is unset.
- **0.2 DB package** — retargeted from `@vercel/postgres` (HTTP) to `pg` on the Neon `-pooler` endpoint; versioned migrations (`drizzle-kit generate` → `migrations/`), a `_health` table, and a `seed` script. Migrations run against Neon's direct endpoint (drizzle strips `-pooler`). Health smoke test in `test/health.test.ts`.
- **0.1 Monorepo scaffold** — scaffolded from `create-t3-turbo`: Turborepo + pnpm, `apps/{nextjs,expo}` + `packages/{api,auth,db,validators,domain,ui}` + `tooling/*`. Renamed scope to `@matops/*`, dropped the unused `tanstack-start` app, added the framework-free `packages/domain`, and promoted the planning docs into `docs/`.
