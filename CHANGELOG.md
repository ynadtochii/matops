# Changelog

One line per shipped slice (see `docs/delivery.md` §4). Newest first.

## Backend review fixes: a test seam for the API, and the bugs it uncovered (ADR 60)

- **`packages/api` had 17k lines of orchestration and no tests.** It has them now: `packages/api/test` drives the real routers through `appRouter.createCaller`, over the real `enforceTenant` middleware and the real SQL, against PGlite. That took **one** injection point instead of three: `ctx.baseDb`. Every base-connection helper (`withTenant`, `getMembership`, `getMemberById`, `getMemberIdForUser`, `listMembersOf`) now takes `exec` as a **required** parameter, because the `exec = db` defaults were the whole problem. A call site that forgot one kept working against the production pool with no compile error, so a test could pass while the code under it never touched the test database.
- **Three critical bugs.** The auth error hook logged the whole Better Auth context, which carries the **app secret** as a top-level property, so every bad request to `/api/auth/*` wrote it to the production log (**rotate the secret on deploy**). A template **timing** edit hard-DELETEd future classes, but `class_participation` and `drop_in` both reference `class.id` with `ON DELETE no action`, so one student booking meant the owner could never move that template again. It now **cancels and revives**, so an occurrence the new timing still covers comes back with its bookings intact and one it drops stays visible as cancelled instead of vanishing. And every recipient of a class email went in one Resend `to:` field, showing each booked student every other student's address; sends are one per recipient now.
- **Nine smaller defects.** `payments.myDues` returns the gym's **bank details** and was on the enrolled tier, so anyone who typed a public 6-digit code could read them (both mobile callers gate on approval now). `deletePushToken` deleted by token with no owner check. Class notifications omitted `timeZone`, so `formatWhen` labelled the new time in UTC and students were told the wrong hour. The reminder sweep had always got this right, so the two disagreed. `template.update` fell back to `ctx.session.user.id`, and since no client sends `instructorId` on an edit, every edit **reassigned the template to whoever opened the form**. Both reminder sweeps stamp "reminded" before sending and then sent serially, so members past the timeout were marked and never messaged; they fan out now. Notifications moved to a new **`ctx.afterCommit`** hook so a network call no longer holds the tenant transaction open, and `academyName` catches its own errors so `notify.ts` keeps the promise its own doc makes. The drop-in upsert overwrote `class_id` and bumped `visit_count` on any repeat submit, erasing the visit a returning lead was recorded against.
- **Two migrations, both small.** `0019` indexes `member (organization_id, user_id)`, because `getMembership` runs on every authenticated request against a table that had only its primary key. `0020` revokes `matops_app`'s INSERT/UPDATE/DELETE on `user` / `organization` / `member` and **all** access to `session` / `account` / `verification` / `invitation` / `academy_invite`: migration `0001` granted DML on ALL tables so new tenant tables would be covered without editing it, and the side effect was full write access to the identity tables, none of which carry a policy.
- **Deletions.** `referral.dashboard` returned `metrics`, `referrerSummaries`, `plans`, `currentMonth`, `timeZone` and a per-student `plan` / `dues` that nothing has read since ADR 56 moved the aggregation to the screen. About 60 lines and a join, gone, with **no client change**. Five copies of the academy-membership guard became one `requireMember(ctx, memberId)`; the `member` table has no RLS policy, so that check is the only thing scoping a member id to the caller's academy.
- **Types.** `ParticipationRow` / `BulkMarkRow` use the `AttendanceStatus` / `BookingStatus` / `BookingTier` unions that already existed and had no consumers; two `as unknown as` casts became `execute<T>()`; `stats.gym` narrows instead of asserting; `createPlan` stopped returning `{ id: string | undefined }` for a value that always exists. `Membership.role` / `.status` stay `string` **on purpose**, because those columns are free text that Better Auth also writes, so a closed union would be a claim the data does not support. Spec §4, S9 + architecture.md §0 updated; ADR [60](docs/issues/60-backend-review-fixes.md). Green: typecheck 17/17 · lint 15/15 · `next build`. Tests written, **not run** (session rule).


## The frontend review is closed out (ADR 59)

- **A crafted join link could rewrite a stranger's profile with no click.** `/join/[token]` auto-fired `membership.join` from the carried `?p=` blob, and `joinPending` writes name and phone to the **global** `user` row. Both halves of that URL are public, so one link sent to any signed-in user renamed them everywhere, made them pending in the sender's academy, and could switch their active tenant. `?p=` is now a **prefill**: the signed-in branch renders the normal join form with the fields filled in and one press finishes it. ADR [59](docs/issues/59-join-link-prefills-only.md), spec S2 updated, join email copy changed. Mobile was never affected (both its join paths need a submit).
- **The dues form matched a member's plan by name and silently moved them.** `membership.members` returned `planName` and no `planId`, so the form fell back to `plans[0]`: an owner editing only the due date of a member on an **archived** plan, or on one of two plans called "Adult", saved them onto a different price. The read now carries `planId`, the picker matches on it, and an archived plan stays selectable **for the member already on it** so a date-only edit no longer forces a plan change.
- **The attendance roster kept its state across a class switch.** `<ClassRoster>` was rendered without a `key`, so React reused the instance when the picker changed class: walk-ins ticked on class A were still counted by "Mark N present" on class B, and pressing it marked people present at a class they did not attend. Keyed on the class id in all three places it is mounted.
- **Rules that live in `packages/domain` are imported now, not re-typed.** `capacityDisplay().isOver` had no caller outside its own test and was inlined at six sites; `attendanceCounts` and `bulkMarkTargets` were reimplemented inside the roster; `DAY_LABELS` was copied; the class-reminder lead time was a second literal that would have drifted from the server's `REMINDER_LEAD_MINUTES`; `spotsLeftLabel` / `clockParts` existed byte-for-byte in both clients. The shared ones moved into the domain package (`booking.ts`, new `format.ts`), and the week grid and the printed poster now share one hour-slot rule (new `grid.ts`) so a gap on paper matches a gap on screen. The drift badge had already diverged — grey on the dashboard, green in the member list — and is one `DriftBadge` in `primitives.tsx`.
- **The mobile query cache outlived the session.** `staleTime: 30_000` plus a cache that neither sign-out nor magic-link verify ever cleared meant the next person to sign in on a shared phone could be served the previous one's academy, classes and stats for half a minute, and the gate would route on it. Both paths call `queryClient.clear()`.
- **Smaller ones, same pass.** The Training tab's hand-rolled cancel dropped the error branch (a rejected cancel was silent there and loud everywhere else) — it uses `useCancelBooking`; its error state also rendered next to "Nothing booked yet" instead of replacing it. Marking a 30-person roster fired 30 refetches of the 15-day class window; the class read is now invalidated once, when the roster closes. The dashboard's drop-in-leads item linked to a tab that could not be selected, and `/members` threw away its own query string on mount — the tab is driven by `?tab=` and the `replaceState` is gone. The week grid's now-line no longer lands on the wrong row for an evening-only gym. The local reminder store's read-modify-write is serialized, so two quick bookings cannot drop an entry and leave a cancelled class reminding.
- **Accessibility + comments.** `Tabs` claimed `role="tablist"` without `aria-controls`, panel ids, roving `tabIndex` or arrow keys; all four uses are plain view switches, so they are a labelled button group now. The `Stat` delta read as a bare number to a screen reader (`aria-label` on a generic `<span>`), the referrals dialog suppressed its own description, and the attendance class picker had no accessible name. About 60 lines of change-narrating comment removed, including two already stale. **No migration.** Green: typecheck 17/17 · lint 15/15. New domain tests in `grid.test.ts`, `format.test.ts` and `booking.test.ts` — **not run here**; `pnpm test`. The mobile fixes want a device pass.

## The student week can live on a home screen (O8, S4, E.4)

- **It was already installable and nothing said so.** The PWA manifest has had `scope: "/"` since W.1, so the student week at `/` has always been add-to-home-screen material; no student would ever have found that out. Reasoning appended to ADR [57](docs/issues/57-student-onboarding-funnel.md).
- **The manifest description stopped being owner-only.** "Schedule, members, and attendance for grappling academies" is what a student reads in the install prompt, and it described an admin tool; it names booking now. **No API, domain, or migration change; no service worker** (still an ADR 42 cut). Spec O8 + S4 updated. Green: typecheck 17/17 · lint 15/15 · `next build`. **Not seen on a device** — the install prompt, the iOS wording and the standalone hide want a real phone.

## Every input is cleaned before it is measured (ADR 58)

- **The schemas bounded length and never looked at content.** `z.string().trim()` keeps zero-width spaces, control characters and the Unicode bidi overrides that make a stored name render backwards, so a member could be saved under a name that reads one way in the roster and another way anywhere else. Phone was worse: `min(3).max(30)` with no charset accepted `<script>alert(1)</script>` and `call me` in the field the gym dials. `@matops/validators` now exports `lineText` / `blockText` / `NameSchema` / `PhoneSchema` / `EmailSchema` / `HttpUrlSchema` / `IdSchema`, and every field in the package composes from them. Each one caps the raw string *before* it transforms it, so a megabyte of junk is thrown out before any regex touches it, and the real bounds are then measured on the cleaned value. Loose on format, strict on charset: `+380 50 999 88 77` and `Renée O'Neill-Souza` still pass.
- **Three input surfaces had no schema at all.** The sign-in server actions validated nothing, and a server action is a public endpoint: whatever the client binds can be posted directly with any value. `sendMagicLinkAction` handed an unbounded string to Better Auth as an email, and `callbackURL` arrived unchecked, which is an open redirect that also lands attacker text inside the sign-in email we send. Both now parse with the same schemas tRPC uses, and `callbackURL` is pinned to a same-site relative path (`//evil.com` reads as a URL to a browser, so a leading-slash test alone is not enough). The join page parses the base64url profile carried in `?p=` instead of trusting it, and the magic-link URL is escaped before it goes into an `href`.
- **Three smaller holes closed on the way past.** `proofUrl` used bare `z.url()`, which accepts `javascript:` and `data:`. Nothing renders it as a link today, so this was a trap for whoever adds the "view receipt" button. `UpdateClassSchema.timeZone` skipped the `isValidTimeZone` refine that both create schemas apply, so a bogus zone reached the DST math on the reschedule path. The schedule week window had no span limit, so one request could ask for a decade of classes; it is capped at 400 days.
- **No API, domain, or migration change**, and no client type changed (every transform is `string` to `string`). Stored rows are not re-validated, so a phone already saved as `"123"` only fails on its next edit. `@matops/validators` now runs vitest like `@matops/domain` does: `pnpm -F @matops/validators test`, 18 tests. ADR [58](docs/issues/58-input-validation-and-sanitization.md). Green: typecheck 17/17 · lint 15/15. **Rate limiting is explicitly not in this pass.** The public procedures and the magic-link action are still unthrottled, which is Phase 5 work.

## Joining on the web is one form and one email (S2, E.2)

- **The email hop sat in the middle of the join, which is the worst place for it.** A student on an invite link had to type an email, leave for their mail app, come back, and only *then* find out there was a name and phone form waiting. Now the form asks name, phone and email together, sends one link, and opening that link **finishes the join on its own** — the one unavoidable app switch is the last step and it returns to "you're in", not to more typing.
- **The profile travels in the link, not in the browser.** `sessionStorage` looks like the obvious place to park it and is wrong: a magic link is regularly opened in a different browser than the form was typed in, where nothing client-side exists. It rides in the `callbackURL` instead, **base64url-encoded rather than as query pairs**, because better-auth runs `decodeURIComponent` on the `callbackURL` a second time at verify — a phone typed as `+380…` was encoded to `%2B`, decoded back to `+`, and would have landed as a **space**. The opaque form is immune to the second decode, passes better-auth's relative-URL `originCheck` regex, and keeps the name and phone out of the emailed URL.
- **Google is unchanged and still works**: it has no mail round trip, so it returns to the plain name-and-phone form. `sign-in.tsx` now exports `SocialSignIn` and `OrDivider` so the join page can reuse the Google button without a second email form beneath it, and the carried profile is read **server-side** in `page.tsx`, so there is no `useSearchParams` Suspense boundary. **No API, domain, or migration change.** Spec S2 updated. Green: typecheck 17/17 · lint 15/15. **Wants a live pass:** the magic-link round trip was reasoned through better-auth's source, not clicked.

## Money reaches the health row (O1, D.5)

- **The owner now sees what the gym actually took this month, next to last month.** New owner-only **`stats.revenue`**: payment claims the owner has **confirmed**, split by academy calendar month. Confirmed is the only honest basis — dues are manual bank transfers (ADR 40), so the money exists once the owner has matched a transfer to a claim and not a moment before. It needed **no new domain rule**: the pure `groupMoneyByCurrency` the referral ledger already had does the summing, and `monthBucket` from D.4 does the split. **Currencies are never added together**, the rule O9 set, so the result is one figure per currency, each carrying its own previous-month total; a currency billed in **either** month appears in both, so a drop to zero is visible rather than silently absent. A gym that has confirmed nothing at all shows no money figure rather than a zero. The SQL bound is a coarse **70 days** — this month plus last is at most 62 on any calendar, and the margin covers the academy time zone shifting a boundary — purely so the query does not grow forever; the exact month split is done in code where the zone is known. **Instructors do not get it**: the insights row is staff-visible, so the query is a separate owner-tier call rather than a field on `stats.gym` (ADR 38 / 52 role split). `Stat` gains an optional `formatDelta`, so the comparison line reads `↑ €120 vs last month` instead of a raw minor-unit count. **No migration or token change.** Spec O1 updated; roadmap D.5 flipped, closing the v2.1 series. Green: typecheck 17/17 · lint 15/15 · `next build`.

## Dashboard numbers now say which way they are going (O1, D.4)

- **Every number on the insights row carried no baseline.** "Visits this week: 84" — good or bad? The owner had no way to tell, which made the whole block decoration rather than insight. `gymInsights` gains **`visitsLastWeek`**, counted in the same loop over the same 30-day window, because this week and last week both fit inside it with room to spare. New exported pure **`monthBucket(instant, timeZone)`** gives `stats.gym` a **`newMembersLastMonth`** beside the existing count, and replaces the router's hand-rolled `sameMonth` string comparison while it is there. Both growth numbers count only retained members, so a joiner who has since left is missing from either side and the pair stays comparable — noted in the code, because it is the kind of bias that looks like a bug later. The `Stat` primitive gains an optional comparison line (`↑ 12 vs last week`, or "Same as last week" at zero), painted in the **muted colour, never green or red**: a drop in visits is not an error, using the callout hues for trend direction would overload a vocabulary design.md gives one meaning each, and direction encoded in hue alone fails colour blindness. **The row is three numbers now** instead of five: visits this week, new members this month (owner), and the attendance rate. **"Visits this month" is gone** — a part-month count says less than the weekly pulse, and its natural baseline, last month, falls outside the 30-day read the block is built on. **`visitsLastMonth` was deliberately not built** for the same reason: widening the window to reach it would silently change what busiest classes, the attendance rate, and the weekday breakdown mean. Since the numbers no longer share one period, the section stopped claiming "Last 30 days" and each stat states its own. **No migration or token change.** Spec O1 updated; roadmap D.4 flipped. Green: typecheck 17/17 · lint 15/15 · `next build`. Domain tests updated and 3 added for `monthBucket`, not run (session rule).
